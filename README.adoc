[[overview]]
== Overview

. _ploaness_ is a quality harness for Payload CMS projects. A project declares one dependency on the `ploaness` package and receives from it the analyzer settings, the xref:#managed-files[managed files], the commit rules, the xref:#payload-usage-rules[], and the checks that run over the code.
. This guide is written for an engineer who adds _ploaness_ version `{ploaness-version}` to a Payload project and then runs its checks. It assumes working knowledge of pnpm, TypeScript, and Payload. It explains xref:#quick-start[how to add the harness], xref:#commands[how to run it], xref:#gates[what it checks], and xref:#configuration[how to configure it]. It doesn't cover the packages that _ploaness_ is built from.

[[quick-start]]
== Quick Start

[[requirements]]
=== Requirements

. _ploaness_ runs on Node 26 or newer. The xref:#preflight-gate[`preflight` gate] stops the run on an older version.
. The project declares `payload` among its dependencies. _ploaness_ judges Payload CMS projects and refuses to judge a project of another kind.
. Four gates run their analyzer in a container: `secrets`, `prose`, `docker`, and `actions`. Each of them needs a reachable Docker daemon and fails without one.

[[installation]]
=== Installation

. Add the dependency and write the wiring:
+
[source,shell]
----
pnpm add -D ploaness
pnpm exec ploaness init
----
. The `ploaness init` command writes the `verify`, `verify:full`, and `format` scripts into `package.json` and creates the xref:#project-files[project files]. It then writes the xref:#managed-files[managed files]. It never overwrites a file that already exists.
. Review and commit the changes.

[[project-files]]
=== Project Files

. A project keeps four settings files of its own in the working tree. Each one points at the shipped settings and adds only what the tool has to read from the project root:
+
[cols="2,5"]
|===
| File | Content

| `biome.json`
| `{ "extends": ["ploaness/biome"] }` and the `files` block that selects what Biome reads.

| `tsconfig.json`
| `{ "extends": "ploaness/tsconfig.json" }`, the project's own `paths`, and the `include` and `exclude` globs.

| `eslint.config.mjs`
| An import of `ploaness/eslint` and its default re-export.

| `vitest.config.mts`
| A re-export of `ploaness/vitest`.
|===
. Biome and TypeScript resolve a relative glob against the directory of the file that declares it. A glob left inside `node_modules` matches nothing in the project, which is why the two blocks sit at the project root. _ploaness_ still owns their text, and the xref:#wiring-gate[`wiring` gate] compares them character for character.
. A project never names an `@ploaness/...` package. Under the `node_modules` layout that pnpm creates, a consumer can't resolve a package it doesn't depend on directly, so every entry point a project needs is re-exported through `ploaness` itself.

[[commands]]
== Commands

. Every command runs through the `ploaness` executable. The xref:#init-command[`ploaness init`] command writes three of them into `package.json`, so `pnpm run verify` reaches the same code as `pnpm exec ploaness verify`:
+
[cols="3,5"]
|===
| Command | Behavior

| [[default-verification,default verification]]`ploaness verify`
| Runs the xref:#default-gates[27 default gates].

| [[extended-verification,extended verification]]`ploaness verify --extended`
| Runs xref:#default-verification[] and the xref:#extended-gates[6 extended gates] as well.

| `ploaness format`
| Rewrites the sources with Biome and applies the fixes ESLint can make on its own.

| [[sync-command,the sync command]]`ploaness sync`
| Writes the xref:#managed-files[managed files] and names the ones it refuses to overwrite.

| [[init-command]]`ploaness init`
| Writes the wiring into a project that doesn't carry it yet.

| `ploaness gate <id>`
| Runs one gate, for debugging.

| `ploaness gates`
| Prints every gate in run order.

| `ploaness commit-message <file>`
| Checks one commit message. It reads `--range <base>..<head>` or `--all` in place of a file.
|===
. [[verification-commands,verification commands]]The two verification commands are xref:#default-verification[] and xref:#extended-verification[]. Both read one flag, [[report-only-mode,report-only mode]]`--enforce=false`, which prints the findings and exits with status `0`. That flag enables no further check, and the status it exits with isn't a pass.
. For example, `ploaness verify --extended --enforce=false` runs xref:#extended-verification[] in xref:#report-only-mode[report-only mode].

[[gates]]
== Gates

. A _gate_ is one named check that a xref:#verification-commands[verification command] runs. A failing gate doesn't stop the run, and every gate reports, so one run names everything that's wrong rather than the first thing only.
. The order is fixed. The structural checks that catch a mis-wired project run before the analyzers whose output would be harder to read, and the fingerprint of the working tree is taken before any gate can rewrite a file.
. The `prose` gate is the one check whose rules the project owns. _ploaness_ ships no house style, because voice, terminology, and audience are the project's decisions. The gate runs Vale against the `.vale.ini` at the repository root and requires a report with no alert at all for `README.adoc`. A project that keeps no `.vale.ini` has declared no prose rules, and the gate passes.

[[default-gates]]
=== Default Verification Gates

[cols="2,5"]
|===
| Gate | Check

| [[preflight-gate,the preflight gate]]`preflight`
| The project declares `payload` and runs on Node 26 or newer.

| [[wiring-gate,the wiring gate]]`wiring`
| The scripts, settings files, and workflows that arm the harness are intact.

| `assets`
| The xref:#managed-files[managed files] match what _ploaness_ ships.

| `tree-snapshot`
| Records a fingerprint of the working tree.

| `types`
| `tsc --noEmit`.

| `biome`
| Formatting and the fast lint pass.

| `biome-schema`
| The `$schema` in `biome.json` names the installed Biome version.

| `eslint`
| The type-aware lint pass.

| `conventions`
| The ban on typographic characters and on hand-written JavaScript.

| `css`
| Stylelint.

| `arch`
| dependency-cruiser.

| `type-coverage`
| Type coverage of 100% over hand-written code, so no `any` survives.

| `payload-generated`
| `payload-types.ts` and `importMap.js` are current.

| `payload-rules`
| The six xref:#payload-usage-rules[].

| `config-refs`
| No analyzer setting carves out a path that no longer exists.

| `secrets`
| gitleaks over the git history, on the tool's own rules.

| `licenses`
| The license of every dependency sits inside the allowlist.

| `deps`
| No dependency is two or more major versions behind. The gate reads the registry and fails when it can't.

| `image-assets`
| Every tracked image decodes as the format its bytes claim.

| `docs`
| The agent documentation names no script and no file that has gone.

| `prose`
| Vale over `README.adoc`.

| `skills`
| The metadata header of every `SKILL.md`.

| `docker`
| hadolint over every Dockerfile, and `docker compose config`.

| `actions`
| actionlint over every workflow.

| `knip`
| Dead code, unused files, and unused dependencies.

| `tests`
| The test suite and its coverage thresholds.

| `tree-verify`
| The working tree is unchanged since `tree-snapshot` ran.
|===

[[extended-gates]]
=== Extended Verification Gates

[cols="2,5"]
|===
| Gate | Check

| `require-full-history`
| The clone carries the whole history rather than a truncated one.

| `commit-history`
| Every commit message in the history, not the newest one only.

| `linear-history`
| No merge commit anywhere in the history.

| `build`
| The production build.

| `bundle`
| The gzipped client JavaScript stays under xref:#bundle-budget[the bundle budget].

| `e2e`
| The end-to-end suite.
|===

[[payload-usage-rules]]
=== Payload Usage Rules

. The `payload-rules` gate reads the project's TypeScript sources and reports these six rules:
+
[cols="3,5"]
|===
| Rule | Requirement

| `no-unbounded-find`
| A `payload.find(...)` call declares `depth` or `limit`.

| `no-unbounded-findbyid`
| A `payload.findByID(...)` call declares `depth`.

| `no-unbounded-findglobal`
| A `payload.findGlobal(...)` call declares `depth`.

| `no-override-access`
| `overrideAccess: true` never appears.

| `no-deep-relative-imports`
| An import uses the `@/` alias rather than a parent-relative `../` path.

| `require-collection-access`
| A `CollectionConfig` declares `access` of its own.
|===
. `require-collection-access` guards a security decision rather than a matter of style. A collection that omits `access` inherits the Payload defaults, which grant public read. A collection meant to be readable by anyone says so, instead of becoming readable because nobody wrote anything down.
. The gate reads a call by scanning for its matching bracket and skipping over string literals, so a call spread across several lines or nested inside another one still reads correctly. Only a call on `payload`, `req.payload`, or `this.payload` counts, and an unrelated `array.find(...)` never does.

[[managed-files]]
== Managed Files

. Git, editors, and coding agents read their settings from the working tree rather than from `node_modules`. _ploaness_ manages the files those tools read, and the xref:#sync-command[] writes them:
+
[cols="2,3,5"]
|===
| Policy | Files | Behavior

| [[managed-section,managed section]]Managed section
| `AGENTS.md`
| _ploaness_ owns the marked block at the top. The project owns the text below it.

| [[pinned-file,pinned file]]Pinned
| `README-guideline-software-project.adoc`, `.ploaness/agent-guide.md`, `CLAUDE.md`, `.editorconfig`, `.gitattributes`, `.nvmrc`, `.npmrc`
| The file exists and matches what the active _ploaness_ version ships, character for character.

| [[seed-file,seed file]]Seed
| `.gitignore`
| The xref:#sync-command[] creates the file once when it's absent. The project owns it afterwards.

| [[forbidden-file,forbidden file]]Forbidden
| `.stylelintrc.json`, `.dependency-cruiser.json`, `knip.json`, `.gitleaks.toml`, `plugins`
| _ploaness_ supplies these settings itself. The path must not exist, because a copy in the tree could only shadow or weaken them.
|===
. `README-guideline-software-project.adoc` states the rules the project is held to, in a form that names no tool. `.ploaness/agent-guide.md` maps those rules onto this harness. Both are xref:#pinned-file[pinned], so raising the _ploaness_ version updates them in every project at once.
. The xref:#managed-section[] in `AGENTS.md` is enclosed by `BEGIN PLOANESS MANAGED INSTRUCTIONS` and `END PLOANESS MANAGED INSTRUCTIONS`. It leads the file and appears exactly once. A block that an agent reaches only after the project's own text no longer governs what comes before it, and a second copy would let one block go stale while the gate still reported the other as current.
. The xref:#sync-command[] creates `AGENTS.md` or refreshes its xref:#managed-section[], carrying the text below the block through unchanged. It refuses a file whose markers are duplicated, incomplete, or no longer leading, because every edit it could make there would either duplicate the block or swallow text the project owns. The `assets` gate names such a file on its own and asks for a repair by hand.
. To let the project own a xref:#pinned-file[], a xref:#seed-file[], or a xref:#forbidden-file[], list its path under xref:#unmanaged-assets[`unmanagedAssets`] together with the reason. _ploaness_ then leaves that path alone. An entry without a reason is dropped, and the path stays managed.

[[configuration]]
== Configuration

. Settings live under the `ploaness` key of `package.json`. Every key is optional, and a project that declares none still receives the whole contract:
+
[source,json]
----
{
  "ploaness": {
    "sourceRoots": ["src"],
    "unmanagedAssets": [{ "path": ".gitignore", "reason": "carries deployment-specific entries" }],
    "typographyExclusions": ["^src/generated/"],
    "javascriptAllowlist": ["^scripts/legacy\\.js$"],
    "coverageExclude": ["src/migrations/**"],
    "bundleBudgetBytes": 921600,
    "pretest": ["pnpm", "run", "db:ensure"],
    "testWrapper": ["pnpm", "run", "db:scratch", "--"],
    "analysisEnv": { "STRIPE_KEY": "placeholder" }
  }
}
----
. Every list key adds to the shipped default rather than replacing it, so a declared value can widen a set but never shrink one:
+
[cols="3,3,5"]
|===
| Key | Default | Use

| `sourceRoots`
| `src`, `tests`, `scripts`
| The directories that hold the project's own source, read by the file-selection and coverage gates.

| [[unmanaged-assets,unmanagedAssets]]`unmanagedAssets`
| empty
| Managed paths the project takes over, each with the reason. The section xref:#managed-files[] names the paths this key accepts.

| `typographyExclusions`
| the generated Payload files
| Path patterns that the ban on typographic characters skips.

| `javascriptAllowlist`
| `eslint.config.mjs`, `importMap.js`
| Path patterns that the ban on hand-written JavaScript skips.

| `coverageExclude`
| the framework glue, the generated files, and the `.tsx` components
| Globs left out of coverage measurement, by the role a file plays rather than by convenience.

| [[bundle-budget,the bundle budget]]`bundleBudgetBytes`
| `921600`
| The ceiling on total gzipped client JavaScript, in bytes.

| `pretest`
| empty
| A command run once before the `tests` and `e2e` gates, given as an argument list.

| `testWrapper`
| empty
| An argument list wrapping the test runner, for a project that runs its suite against a scratch database.

| `analysisEnv`
| `PAYLOAD_SECRET`, `DATABASE_URL`
| Placeholder environment variables for the gates that import the project to read it.
|===
. `pretest` and `testWrapper` exist because a Payload suite needs a database before it can start, and how a project reaches one is a fact _ploaness_ can't know. Declaring either one weakens no rule. The gates and their thresholds don't change, and only the route to the database does.
. `analysisEnv` exists because a Payload configuration reads `process.env` as soon as the module loads, which a reader that only inspects the code can't satisfy in a bare shell. The values are placeholders. Nothing connects to them, and a gate that runs the application, such as `build`, `tests`, or `e2e`, uses the real environment instead.
. No key turns a gate off. A failing check is a finding to repair rather than a setting to change.
