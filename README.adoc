[[overview]]
== Overview

. _ploaness_ is a quality harness for https://payloadcms.com[Payload CMS^] projects.
. A project declares `ploaness` as a development dependency and receives the analyzer settings, the commit rules, the xref:#managed-files[managed files], and the xref:#gates[gates] that inspect the project. Analyzer configurations are inherited. Managed files are written into the project and checked for drift.
. This guide is written for an engineer who attaches _ploaness_ version `{ploaness-version}` to a https://payloadcms.com[Payload CMS^] project, or works day to day in a project that already runs the harness. The guide covers what the harness does, what the harness requires, and the steps that attach the harness. The guide doesn't state the individual rules, which _ploaness_ installs into the project for the coding agent that repairs them.

[[harness-structure]]
== Harness Structure

[[gates]]
=== Gates

. A [[gate,gate]]_gate_ is one named verification that a xref:#commands[command] runs, and a [[finding,finding]]_finding_ is one problem a gate reports. Default verification runs 38 gates. Extended verification adds eight more, covering the shell scripts, the infrastructure definitions, the history, the production build, the client bundle, and the browser suite.
. A run stops at the first failing gate and names how many gates the run didn't reach. Stopping there is deliberate: a gate is free to leave the tree in a shape the next gate misreads, and a column of passes beneath a failure would describe a state nobody established.

[[managed-files]]
=== Managed Files

_ploaness_ owns the text of certain files in the project, among them the editor settings, the ignore files, and the agent instructions. `ploaness sync` writes those files, and a gate reports any that were edited afterwards. A managed file is owned rather than suggested for the reason a rule is: a check a project can rewrite isn't a check.

[[requirements]]
== Requirements

. Use Node 26 or newer, the pnpm version pinned by _ploaness_, and Git.
. Include at least one application that declares the https://www.npmjs.com/package/payload[`payload` package^].
. Use the dependency versions pinned by _ploaness_.
. Declare `@ploaness/runtime` in each application's `dependencies`, matching its `ploaness` version.
. Provide a reachable Docker daemon and network access to the package and advisory registries.

[[adding-ploaness-to-a-project]]
== Adding _ploaness_ to a Project

. Add the package:
+
[source,bash,subs="attributes+"]
----
pnpm add -D ploaness@{ploaness-version}
----
. Write the wiring and the xref:#managed-files[managed files]:
+
[source,bash]
----
pnpm exec ploaness init && pnpm install
----
+
`ploaness init` writes the project's scripts, creates the configuration files that point at the shipped settings, and materializes the xref:#managed-files[managed files]. Existing member configurations are left in place. Root scripts and managed content are updated.
. Hand the project to a coding agent and ask the agent to bring the project up to the harness. `ploaness init` has already written the instructions that agent reads: a managed block at the top of `AGENTS.md` points at `.ploaness/agent-guide.md`, which describes the harness and the order to work in.

[[commands]]
== Commands

Every command runs through the `ploaness` executable:

[cols="3,5"]
|===
| Command | Behavior

| `ploaness verify`
| Runs the default verification gates. Written as `pnpm run verify`.

| `ploaness verify --extended`
| Runs the default verification gates and the eight extended gates as well. Written as `pnpm run verify:full`.

| `ploaness format`
| Rewrites the files Biome selects and applies the fixes ESLint can make unaided. Written as `pnpm run format`.

| `ploaness sync`
| Writes the xref:#managed-files[managed files], and names every file `ploaness sync` refuses to overwrite.

| `ploaness init`
| Writes the scripts, the configuration files, and the xref:#managed-files[managed files].

| `ploaness gate <id> [--verbose]`
| Runs one xref:#gate[gate]. `--verbose` also prints the whole unedited output of that gate's analyzer.

| `ploaness gates`
| Prints every xref:#gate[gate] in run order.

| `ploaness commit-message <file>`
| Verifies one commit message. `ploaness commit-message` reads `--range <base>..<head>` or `--all` in place of a file.
|===

Both verification commands read one flag, `--enforce=false`, which carries the run past a failing xref:#gate[gate] instead of stopping there, so a single run lists xref:#finding[findings] across gates. Failed preconditions still stop the run. The run then exits with status `0`, and that status isn't a pass. Reach for the flag to measure the size of the job, not to declare the job done.

[[installed-documentation]]
== Installed Documentation

`ploaness init` installs the full contract into the project, where the agent working on that project reads the contract:

[cols="2,5"]
|===
| Path | Content

| `.ploaness/agent-guide.md`
| Harness usage, every setting, and the order the commands run in. Read `.ploaness/agent-guide.md` before repairing a xref:#finding[finding].

| `README-guideline-software-project.adoc`
| The governing standard the harness maps onto. The standard states the rules themselves.

| `AGENTS.md`
| A managed block naming `.ploaness/agent-guide.md` and `README-guideline-software-project.adoc`, in the order an agent reads those two documents, followed by whatever the project wants to add.
|===
