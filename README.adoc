[[overview]]
== Overview

. _ploaness_ is a quality harness for https://payloadcms.com[Payload CMS^] projects. A https://payloadcms.com[Payload CMS^] project declares one dependency on the `ploaness` package and receives from it the analyzer settings, the xref:#managed-files[managed files], the commit rules, the xref:#payload-cms-usage-rules[], and the xref:#gates[gates] that inspect it.
. This guide is written for an engineer who adds _ploaness_ version `{ploaness-version}` to a https://payloadcms.com[Payload CMS^] project and then runs its xref:#verification-commands[verification commands]. It explains xref:#quick-start[how to add _ploaness_], xref:#commands[how to run it], xref:#gates[what each gate verifies], and xref:#configuration[how to configure it].

[[quick-start]]
== Quick Start

[[requirements]]
=== Requirements

. _ploaness_ runs on Node 26 or newer.
. The https://payloadcms.com[Payload CMS^] project declares the https://www.npmjs.com/package/payload[`payload` package^] among its dependencies. Every rule _ploaness_ applies is a rule about https://payloadcms.com[Payload CMS^].
. Three xref:#gates[gates] run their analyzer in a container: xref:#secrets-gate[`secrets`], xref:#docker-gate[`docker`], and xref:#actions-gate[`actions`]. Each analyzer needs a reachable Docker daemon, and each image is pinned by digest so an upstream release can't change a verdict.
. Two xref:#gates[gates] read a public service by design and fail when it's unreachable: xref:#vulnerabilities-gate[`vulnerabilities`] reads the advisory database, and `deps` reads the package registry.
. _ploaness_ pins two sets of versions, and the xref:#wiring-gate[`wiring` gate] rejects any other value for either.
+
The *toolchain* is every package whose version changes what a xref:#gates[gate] does: `vitest`, `@vitest/coverage-v8`, `typescript`, `jsdom`, `fast-check`, the `@testing-library` packages, `@playwright/test`, `@axe-core/playwright`, and `tsx`, which the xref:#e2e-gate[`e2e`] gate starts the run through. A https://payloadcms.com[Payload CMS^] project declares the ones its own files import and declares the rest only if it uses them, at the pinned version either way. The expected version is read from _ploaness_'s own manifests, so there is no second copy to drift.
+
The *framework* is `payload`, `next`, `react`, `react-dom`, `sharp`, and `graphql`, which https://payloadcms.com[Payload CMS^] declares as a peer, together with the type definitions that describe the framework and the runtime beneath it: `@types/node`, `@types/react`, and `@types/react-dom`. Every governed https://payloadcms.com[Payload CMS^] project declares all nine. The framework packages are what the xref:#preflight-gate[`preflight` gate] already assumes; the type packages are pinned for the toolchain's reason rather than the framework's, because a type package is an input to the type checker and a patch release changes what type-checks while the project stays unchanged.
+
The *ecosystem* is `pg`, `@types/pg`, `dotenv`, and `cross-env`. _ploaness_ owns the version of each so no two governed projects disagree about one, and requires none of them, because a https://payloadcms.com[Payload CMS^] project on MongoDB has no Postgres driver and requiring one would make _ploaness_ dictate a database rather than a version. An unrequired pin is matched when the project declares it and forced on nobody.
+
These versions are written in `pins.json` rather than declared as dependencies of _ploaness_, because _ploaness_ imports none of them and declaring them would install a second https://payloadcms.com[Payload CMS^], Next, React, or set of type definitions into a project that already has one. Two copies of `@types/react` in one dependency tree is a class of type error that reads as the project's fault. Each group in that file carries the rule that applies to it, so adding a group changes no code.
. `packageManager` is pinned to an exact package-manager version, and the `engines` block states the runtime _ploaness_ requires. Corepack runs exactly the package manager named, so it decides how every other pinned version resolves: the same lockfile can produce a different tree under a different one, which would make every pin above it a statement about a graph nobody built. The xref:#preflight-gate[`preflight` gate] reads the Node that is actually running; the `engines` block is the separate statement a https://payloadcms.com[Payload CMS^] project makes to an installer, a container image, and a reader.
. Every `@payloadcms/...` package a https://payloadcms.com[Payload CMS^] project declares carries the pinned `payload` version. https://payloadcms.com[Payload CMS^] fails at runtime when its own packages disagree, and the rule is derived from the pin rather than written as a list, so a project that adds a https://payloadcms.com[Payload CMS^] plugin is covered by the rule that already exists.
. No declared dependency carries a range. A `^`, `~`, comparator, wildcard, or partial version resolves to whichever release is newest at install time, which is the same hole pinning the toolchain closes, one layer down: the xref:#build-gate[`build`], xref:#tests-gate[`tests`], and xref:#e2e-gate[`e2e`] gates would run against something nobody wrote down. A specifier naming an artefact rather than a range, such as a local tarball or a workspace link, is not a range and is left alone.
. An install override may redefine a package the https://payloadcms.com[Payload CMS^] project does *not* declare, and may not redefine one it does. The permitted case is a transitive package carrying an advisory with no upgrade path above it, which the project can reach no other way. The forbidden case is a package whose version the project already wrote down: two declarations of one version don't stay equal, and the one that loses is the one every reader believes.

[[installation]]
=== Installation

. Add and xref:#init-command[initialize] _ploaness_:
+
[source,shell]
----
pnpm add -D ploaness
pnpm exec ploaness init
----
. The xref:#init-command[`ploaness init` command] writes three [[project-scripts,project scripts]]_project scripts_ into `package.json`: `verify`, `verify:full`, and `format`. It then creates the xref:#project-files[project files] and writes the xref:#managed-files[managed files]. It never overwrites a file that already exists.
. Review and commit the changes.

[[project-files]]
=== Project Files

. A https://payloadcms.com[Payload CMS^] project keeps five project files of its own in the working tree. Each project file points at the shipped analyzer settings and adds only what the analyzer has to read from the repository root:
+
[cols="2,5"]
|===
| File | Content

| `biome.json`
| `{ "extends": ["ploaness/biome"] }` and the `files` block that selects what Biome reads.

| `tsconfig.json`
| `{ "extends": "ploaness/tsconfig.json" }`, the https://payloadcms.com[Payload CMS^] project's own `paths`, and the `include` and `exclude` globs.

| `eslint.config.mjs`
| An import of `ploaness/eslint` and its default re-export.

| `vitest.config.mts`
| A re-export of `ploaness/vitest`.

| `playwright.config.ts`
| A re-export of `ploaness/playwright`.
|===
. Biome and TypeScript resolve a relative glob against the directory of the file that declares it. A glob left inside `node_modules` matches no file in the working tree, which is why the two blocks sit at the repository root. _ploaness_ still owns their text, and the xref:#wiring-gate[`wiring` gate] compares them character for character.
. A https://payloadcms.com[Payload CMS^] project never names an `@ploaness/...` package. Under the `node_modules` layout that pnpm creates, a https://payloadcms.com[Payload CMS^] project can't resolve a package it doesn't depend on directly, so every entry point it needs is re-exported through `ploaness` itself.

[[commands]]
== Commands

. Every command runs through the `ploaness` executable. The xref:#init-command[`ploaness init`] command writes the three xref:#project-scripts[project scripts] into `package.json`, so xref:#default-verification[`pnpm run verify`] invokes the same implementation as `pnpm exec ploaness verify`:
+
[cols="3,5"]
|===
| Command | Behavior

| [[default-verification,default verification]]`ploaness verify`
| Runs the xref:#default-gates[31 default verification gates].

| [[extended-verification,extended verification]]`ploaness verify --extended`
| Runs xref:#default-verification[] and the xref:#extended-gates[6 extended verification gates] as well.

| `ploaness format`
| Rewrites the files selected by Biome and applies the fixes ESLint can make on its own.

| [[sync-command,the sync command]]`ploaness sync`
| Writes the xref:#managed-files[managed files] and names the ones it refuses to overwrite.

| [[init-command]]`ploaness init`
| Writes the xref:#project-scripts[project scripts], xref:#project-files[project files], and xref:#managed-files[managed files].

| `ploaness gate <id>`
| Runs one xref:#gates[gate], for debugging.

| `ploaness gates`
| Prints every xref:#gates[gate] in run order.

| `ploaness commit-message <file>`
| Verifies one commit message. It reads `--range <base>..<head>` or `--all` in place of a file.
|===
. [[verification-commands,verification commands]]The two verification commands are xref:#default-verification[] and xref:#extended-verification[]. Both read one flag, [[report-only-mode,report-only mode]]`--enforce=false`, which prints the xref:#finding[findings] and exits with status `0`. That flag enables no further xref:#gates[gate], and the status it exits with isn't a pass. It's for adopting _ploaness_, not for running it, and every run in that mode says so in its own output.
. For example, xref:#extended-verification[`ploaness verify --extended --enforce=false`] runs the xref:#default-gates[default verification gates] and xref:#extended-gates[extended verification gates] in xref:#report-only-mode[report-only mode].

[[gates]]
== Gates

. A _gate_ is one named verification operation that a xref:#verification-commands[verification command] runs. A failing gate doesn't stop the run.
. A [[finding]]_finding_ is one problem reported by a gate. Every gate completes, so one run reports every finding rather than the first finding only. An analyzer's native output has its own name and becomes a finding only when a gate reports it.
. The gate order is fixed. The structural gates that catch a mis-wired https://payloadcms.com[Payload CMS^] project run before the analyzers whose output would be harder to read, and the xref:#tree-snapshot-gate[fingerprint of the working tree] is taken before any gate can rewrite a file.

[[default-gates]]
=== Default Verification Gates

xref:#default-verification[] runs the following 31 gates.

[cols="2,5"]
|===
| Gate | Behavior

| [[preflight-gate]]`preflight`
| The https://payloadcms.com[Payload CMS^] project meets the xref:#requirements[].

| [[wiring-gate,the wiring gate]]`wiring`
| The xref:#project-scripts[project scripts] and xref:#project-files[project files] that arm _ploaness_ are intact, and nothing in the https://payloadcms.com[Payload CMS^] project undoes them: a xref:#project-files[project file] can't be replaced by a local one, and an install override can't redefine a version _ploaness_ pins. Where verification runs is the project's own decision, so the gate rules on nothing outside the repository's own files.

| [[assets-gate]]`assets`
| The xref:#managed-files[managed files] match what _ploaness_ ships.

| [[tree-snapshot-gate]]`tree-snapshot`
| Records a fingerprint of the working tree.

| `types`
| `tsc --noEmit`.

| `biome`
| Formatting and the fast lint pass.

| `biome-schema`
| The `$schema` in `biome.json` names the installed Biome version.

| `eslint`
| The type-aware lint pass.

| `conventions`
| The ban on typographic characters and on hand-written JavaScript, across every tracked text file.

| [[editorconfig-gate]]`editorconfig`
| Every tracked text file matches the pinned `.editorconfig`, and no code line passes 120 characters.

| [[suppressions-gate]]`suppressions`
| The suppression count against xref:#suppression-ceiling[the suppression ceiling], over the https://payloadcms.com[Payload CMS^] project's own files rather than the xref:#managed-files[managed] ones.

| `css`
| Stylelint.

| `arch`
| dependency-cruiser.

| `type-coverage`
| Type coverage of 100% over hand-written TypeScript.

| `payload-generated`
| The generated https://payloadcms.com[Payload CMS^] artefacts are current.

| [[generated-denial-gate]]`generated-denial`
| The agent runtime is denied write access to every generated artefact.

| [[payload-rules-gate]]`payload-rules`
| The six xref:#payload-cms-usage-rules[].

| `config-refs`
| No analyzer setting carves out a path that no longer exists, and no declared exclusion matches nothing the gate it narrows would have judged.

| [[secrets-gate]]`secrets`
| gitleaks over the git history, on the tool's own rules plus the declared `secretAllowlist`.

| `licenses`
| The license of every dependency sits inside the allowlist.

| [[vulnerabilities-gate]]`vulnerabilities`
| No package in the resolved set carries a known vulnerability at or above the declared severity. The
  advisory database must be reachable.

| [[install-scripts-gate]]`install-scripts`
| The https://payloadcms.com[Payload CMS^] project names the dependencies permitted to run a build or
  postinstall script. An empty list is a valid answer; leaving the list undeclared is not.

| `deps`
| No dependency is two or more major versions behind. The registry must be reachable.

| `image-assets`
| Every tracked image decodes as the format its bytes claim.

| `docs`
| The agent documentation names no xref:#project-scripts[project script] and no file that has gone.

| `skills`
| The metadata header of every `SKILL.md`.

| [[docker-gate]]`docker`
| hadolint over every Dockerfile, and `docker compose config`.

| [[actions-gate]]`actions`
| actionlint over every workflow.

| `knip`
| Dead code, unused files, and unused dependencies.

| [[tests-gate]]`tests`
| The test suite and its coverage thresholds.

| `tree-verify`
| The working tree is unchanged since the xref:#tree-snapshot-gate[`tree-snapshot` gate] ran.
|===

xref:#extended-verification[] adds the following six gates to xref:#default-verification[].

[cols="2,5"]
|===
| Gate | Behavior

| `require-full-history`

[[payload-cms-usage-rules]]
=== https://payloadcms.com[Payload CMS^] Usage Rules

. The xref:#payload-rules-gate[`payload-rules` gate] reads the https://payloadcms.com[Payload CMS^] project's TypeScript source files and reports these rules:
+
[cols="3,5"]
|===
| Rule | Requirement

| `no-unbounded-find`
| A `payload.find(...)` call declares `depth` or `limit`.

| `no-unbounded-findbyid`
| A `payload.findByID(...)` call declares `depth`.

| `no-unbounded-findglobal`
| A `payload.findGlobal(...)` call declares `depth`.

| `no-override-access`
| `overrideAccess: true` never appears.

| `no-deep-relative-imports`
| An import uses the `@/` alias rather than a parent-relative `../` path.

| [[require-complete-access-rule]]`require-complete-access`
| A `CollectionConfig` decides `create`, `read`, `update` and `delete`; a `GlobalConfig` decides `read`
  and `update`.

| `require-auth-hardening`
| A collection with `auth` enabled declares `maxLoginAttempts` and `lockTime`.

| `no-anonymous-draft-reads`
| A config with `versions.drafts` enabled doesn't grant an unconditionally true `read`.
|===
. The xref:#require-complete-access-rule[`require-complete-access` rule] guards a security decision rather than a matter of style. https://payloadcms.com[Payload CMS^] fills the operations a config leaves out during sanitisation, and its default grants public read, so a partial `access` block is invisible the moment the application boots. A collection meant to be readable by anyone declares that in writing, one operation at a time.
. `no-anonymous-draft-reads` covers what follows from that. A draft is unpublished content, and `?draft=true` serves it to whoever the read rule admits, so a read that is unconditionally true publishes every draft. Only the inline always-true form is detectable from the source; a read delegated to a helper is a judgement `.ploaness/agent-guide.md` states in prose.
. The xref:#payload-rules-gate[`payload-rules` gate] reads a call by scanning for its matching bracket and skipping over string literals, so a call spread across several lines or nested inside another one still reads correctly. Only a call on `payload`, `req.payload`, or `this.payload` counts, which is what leaves an unrelated `array.find(...)` alone.

[[managed-files]]
== Managed Files

. Git, editors, and coding agents read their configuration and instructions from the working tree rather than from `node_modules`. _ploaness_ manages the files that carry those inputs, and the xref:#sync-command[] writes them:
+
[cols="2,3,5"]
|===
| Policy | Files | Behavior

| [[managed-section,managed section]]Managed section
| `AGENTS.md`
| _ploaness_ owns the xref:#managed-section[managed section] at the top. The https://payloadcms.com[Payload CMS^] project owns the text below it.

| [[pinned-file,pinned file]]Pinned file
| `README-guideline-software-project.adoc`, `.ploaness/agent-guide.md`, `CLAUDE.md`, `.editorconfig`, `.gitattributes`, `.nvmrc`, `.npmrc`, `tests/e2e/a11y.e2e.spec.ts`
| The xref:#pinned-file[pinned file] exists and matches what the active _ploaness_ version ships, character for character.

| [[seed-file,seed file]]Seed file
| `.gitignore`
| The xref:#sync-command[] creates the xref:#seed-file[seed file] once when it's absent. The https://payloadcms.com[Payload CMS^] project owns the seed file afterwards.

| [[forbidden-file,forbidden file]]Forbidden file
| `.stylelintrc.json`, `.dependency-cruiser.json`, `knip.json`, `.gitleaks.toml`, `plugins`
| _ploaness_ supplies the analyzer settings for each xref:#forbidden-file[forbidden file]. A forbidden file must not exist, because a copy in the working tree could only shadow or weaken those settings.

| [[reference-file,reference file]]Reference file
| `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`
| The entry-point file a coding agent other than Claude reads. A xref:#reference-file[reference file] need not exist, and the xref:#sync-command[] never writes one, because which agents a https://payloadcms.com[Payload CMS^] project uses is the project's own decision. One that does exist carries nothing but a pointer at `AGENTS.md`: the rules live in the root instruction file, so no two agents are held to two contracts. The form of the pointer is the tool's own, so the check reads for the name rather than demanding one spelling.
|===
. `README-guideline-software-project.adoc` states the rules the https://payloadcms.com[Payload CMS^] project is held to, in a form that names no tool. `.ploaness/agent-guide.md` maps those rules onto _ploaness_. Both are xref:#pinned-file[pinned], so raising the _ploaness_ version updates them in every https://payloadcms.com[Payload CMS^] project at once.
. [[accessibility-sweep,the accessibility sweep]]`tests/e2e/a11y.e2e.spec.ts` is the one xref:#pinned-file[] that runs rather than being read. It crawls every public route reachable from the home page and runs https://github.com/dequelabs/axe-core[axe^] on each one, in its default state and with every interactive control driven into `:hover` and `:focus`. A static rule can't reach a contrast defect that appears only in one of those states, and a hand-maintained list of pages to scan is a list somebody eventually forgets to extend, so a page linked anywhere on the site is checked from the moment it exists. It's xref:#pinned-file[pinned] for the reason every other rule belongs to _ploaness_: a check the https://payloadcms.com[Payload CMS^] project can edit isn't a rule.
. The xref:#accessibility-sweep[] carries one scoped lint exemption that its crawl needs. The xref:#suppressions-gate[`suppressions` gate] counts neither that exemption nor the lines around it, because a https://payloadcms.com[Payload CMS^] project can't remove a suppression inside a file it doesn't own, and a xref:#suppression-ceiling[ceiling] earned by code the project didn't write would be an allowance rather than a measure.
. The xref:#managed-section[] in `AGENTS.md` is enclosed by `BEGIN PLOANESS MANAGED INSTRUCTIONS` and `END PLOANESS MANAGED INSTRUCTIONS`. It leads the file and appears exactly once. A managed section that an agent reaches only after the https://payloadcms.com[Payload CMS^] project's own text no longer governs what comes before it, and a second copy would let one managed section go stale while the xref:#assets-gate[`assets` gate] still reported the other as current.
. The xref:#sync-command[] creates `AGENTS.md` or refreshes its xref:#managed-section[], carrying the text below the managed section through unchanged. It refuses a file whose markers are duplicated, incomplete, or no longer leading, because every edit it could make there would either duplicate the managed section or swallow text the https://payloadcms.com[Payload CMS^] project owns. The xref:#assets-gate[`assets` gate] names such a file on its own and asks for a repair by hand.
. To let the https://payloadcms.com[Payload CMS^] project own a xref:#pinned-file[], a xref:#seed-file[], or a xref:#forbidden-file[], list its path under xref:#unmanaged-assets[`unmanagedAssets`] together with the reason. _ploaness_ then leaves that path alone. An entry without a reason is dropped, so _ploaness_ continues to apply the file's policy.

[[configuration]]
== Configuration

. _ploaness_ configuration lives under the `ploaness` key of `package.json`. Every key is optional, and a https://payloadcms.com[Payload CMS^] project that declares none still receives the whole contract:
+
[source,json]
----
{
  "ploaness": {
    "sourceRoots": ["src"],
    "unmanagedAssets": [{ "path": ".gitignore", "reason": "carries deployment-specific entries" }],
    "typographyExclusions": [
      { "pattern": "^src/generated/", "reason": "generated by the framework, not authored here" }
    ],
    "javascriptAllowlist": [
      { "pattern": "^scripts/legacy\\.js$", "reason": "loaded as JavaScript by a tool that reads it" }
    ],
    "coverageExclude": [
      { "pattern": "src/migrations/**", "reason": "generated migrations, with no hand-written logic" }
    ],
    "bundleBudgetBytes": 921600,
    "maxSuppressions": 12,
    "vulnerabilitySeverity": "low",
    "vulnerabilityAllowlist": [
      { "advisory": "GHSA-93q8-gq69-wqmw", "reason": "reachable only through the dev server", "addedOn": "2026-08-23" }
    ],
    "secretAllowlist": [
      { "path": "tests/fixtures/stripe-webhook.json", "reason": "fake test key the checkout fixture asserts on" }
    ],
    "serverUrl": "http://localhost:3000",
    "pretest": ["pnpm", "run", "db:ensure"],
    "testWrapper": ["pnpm", "run", "db:scratch", "--"],
    "analysisEnv": { "STRIPE_KEY": "placeholder" }
  }
}
----
. Every list-valued _ploaness_ configuration key adds to the shipped default rather than replacing it:
+
[cols="3,3,5"]
|===
| Key | Default | Use

| `sourceRoots`
| `src`, `tests`, `scripts`
| The directories that hold the https://payloadcms.com[Payload CMS^] project's own source files, read by the xref:#gates[gates] that select files and measure coverage.

| [[unmanaged-assets,unmanagedAssets]]`unmanagedAssets`
| empty
| xref:#managed-files[Managed files] the https://payloadcms.com[Payload CMS^] project takes over.

| [[declared-exclusion,a declared exclusion]]`typographyExclusions`
| the generated https://payloadcms.com[Payload CMS^] files
| Patterns the ban on typographic characters skips. Each entry is a `pattern` and the `reason` it's
  excluded.

| `javascriptAllowlist`
| `eslint.config.mjs`, `importMap.js`
| Patterns the ban on hand-written JavaScript skips, in the same shape.

| `coverageExclude`
| the framework glue, the generated files, and the `.tsx` components
| Patterns left out of coverage measurement, in the same shape.

| [[bundle-budget,the bundle budget]]`bundleBudgetBytes`
| `921600`
| The ceiling on total gzipped client JavaScript, in bytes. Only a smaller value is honoured.

| [[max-suppressions]]`maxSuppressions`
| unset
| A xref:#suppression-ceiling[suppression ceiling] stricter than the earned one. `0` states that no
  suppression is permitted. A value looser than the earned ceiling is ignored.

| `vulnerabilitySeverity`
| `moderate`
| The severity at which the xref:#vulnerabilities-gate[`vulnerabilities` gate] fails. Only a stricter
  value is honoured.

| `vulnerabilityAllowlist`
| empty
| Advisories the https://payloadcms.com[Payload CMS^] project can't reach. Each entry records the
  `advisory`, the `reason`, and the `addedOn` date. An entry missing any of the three is dropped, and an
  entry that suppresses nothing fails the gate.

| `secretAllowlist`
| empty
| Fake credentials committed as test fixtures. Each entry records the `path` and the `reason`. _ploaness_
  renders the scanner's configuration from these entries outside the working tree, so an entry can only
  add a named exception and never replaces the scanner's own rules. An entry without a reason is dropped.

| [[pretest]]`pretest`
| empty
| A command run once before the xref:#tests-gate[`tests`], xref:#build-gate[`build`], and xref:#e2e-gate[`e2e`] gates, given as an argument list.

| [[test-wrapper]]`testWrapper`
| empty
| An argument list wrapping the process run by the xref:#tests-gate[`tests`], xref:#build-gate[`build`], and xref:#e2e-gate[`e2e`] gates, for a https://payloadcms.com[Payload CMS^] project that uses a scratch database.

| [[analysis-env]]`analysisEnv`
| `PAYLOAD_SECRET`, `DATABASE_URL`
| Placeholder environment variables for the xref:#gates[gates] that import the https://payloadcms.com[Payload CMS^] project to read it.

| [[server-url]]`serverUrl`
| `http://localhost:3000`
| The origin the xref:#e2e-gate[`e2e`] gate drives, for a https://payloadcms.com[Payload CMS^] project that serves on another port.

| [[skip-routes]]`accessibilitySkipRoutes`
| `/admin`, `/api`
| Route prefixes xref:#accessibility-sweep[the accessibility sweep] doesn't follow. Each entry states the `pattern` and the `reason`, as any other xref:#declared-exclusion[] does.
|===
. xref:#pretest[`pretest`] and xref:#test-wrapper[`testWrapper`] exist because a https://payloadcms.com[Payload CMS^] project can need a database before a xref:#gates[gate] can run. How the https://payloadcms.com[Payload CMS^] project reaches that database is a fact _ploaness_ can't know. Declaring either key changes only the route to the database, never a gate or a threshold.
. xref:#pretest[`pretest`] and xref:#test-wrapper[`testWrapper`] are the two keys no check verifies. Both are arbitrary argument lists, and a wrapper that swallows the exit code of the process it wraps is indistinguishable from one that passes it through until it runs. So the rule is stated in `.ploaness/agent-guide.md` instead: the wrapper passes the child's exit code through unchanged, doesn't retry, doesn't filter output, and doesn't decide what runs, and the xref:#pretest[] command provisions rather than editing the tree under verification. Either key used to turn a failing run into a passing one is a bypass, and no xref:#finding[] reports it.
. xref:#server-url[`serverUrl`] and xref:#skip-routes[`accessibilitySkipRoutes`] are the whole of what a https://payloadcms.com[Payload CMS^] project declares about xref:#accessibility-sweep[the accessibility sweep], because the sweep itself is xref:#pinned-file[pinned]. Neither weakens it: the port is a fact _ploaness_ can't know, and the route prefixes add to the two that a https://payloadcms.com[Payload CMS^] project always carries rather than replacing them. The admin panel and the REST API are skipped by default because neither is a public page, and https://payloadcms.com[Payload CMS^] renders the markup behind both.
. xref:#analysis-env[`analysisEnv`] exists because a https://payloadcms.com[Payload CMS^] configuration module reads `process.env` as soon as the module loads, which a reader that only inspects the source files can't satisfy in a bare shell. The values are placeholders, and a xref:#gates[gate] that runs the application, such as xref:#build-gate[`build`], xref:#tests-gate[`tests`], or xref:#e2e-gate[`e2e`], uses the real environment instead.
. [[suppression-ceiling,the suppression ceiling]]The _suppression ceiling_ is `2` plus one for every
`500` non-blank lines of the https://payloadcms.com[Payload CMS^] project's own source. It is a density
rather than a bare count, so it neither strangles a small project nor loosens as a large one grows.
_ploaness_ owns the formula; xref:#max-suppressions[`maxSuppressions`] can only lower the result. The
xref:#suppressions-gate[`suppressions` gate] reports the count and the distance left on every run,
whether it passes or fails, so the trend is readable before the ceiling is reached.
. An xref:#declared-exclusion[] narrows a xref:#gates[gate], which _ploaness_ permits only by file role. So each entry states the role it claims, and the xref:#wiring-gate[`wiring` gate] rejects one that states none, or that names a single file that exists rather than a shape. An entry without a reason is dropped, which makes the gate stricter rather than looser.
. `sourceRoots` adds to the shipped roots rather than replacing them, and no key raises a threshold: a stricter `bundleBudgetBytes`, `maxSuppressions`, or `vulnerabilitySeverity` is honoured, and a looser one is ignored.
. No key turns a xref:#gates[gate] off. A failing gate produces a xref:#finding[finding] to repair.
